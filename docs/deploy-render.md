# Деплой на Render.com — пошагово

Всё поднимается одним Blueprint из `render.yaml` в корне репозитория. Render сам создаёт:

| Ресурс | Что это | План |
|---|---|---|
| `mise-db` | PostgreSQL 16 | free (живёт 30 дней) |
| `mise-redis` | Key Value (Redis) — SignalR и управление симулятором | free |
| `mise-api` | API (.NET, Docker) — `/health`, `/api/v1`, `/hubs/stock` | free |
| `mise-web` | Веб-приложение (nginx: SPA + прокси на API) — его адрес и открываем | free |

HTTPS — из коробки на `*.onrender.com`. Обновления — автоматически при push в `main`.

> Бесплатный план: сервис засыпает через 15 минут без запросов, первый запрос будит его 30–60 с.
> Перед показом откройте сайт за пару минут. Grafana и симулятор на Render не поднимаются (симулятор — только платный worker, см. в конце).

---

## 0. Подготовка (один раз, на своей машине)

1. Код запушен в GitHub: `git push origin main` (Render берёт ветку `main`).
2. **Ключ для пушей** (по желанию; без него приложение работает, только без уведомлений на телефон):
   ```powershell
   docker compose run --rm --no-deps api --generate-vapid-keys
   ```
   Скопируйте строку **закрытого** ключа (Private key) — она понадобится на шаге 2.

## 1. Аккаунт и доступ к GitHub

1. Зайдите на <https://render.com> → **Get Started** → войдите через **GitHub**.
2. Render попросит доступ к репозиториям — разрешите доступ к `andwhy67/mise` (или ко всем).

## 2. Blueprint

1. В Dashboard: **New +** (справа сверху) → **Blueprint**.
2. Выберите репозиторий **mise** → **Connect**.
3. **Blueprint Name**: `mise`. **Branch**: `main`. Render прочитает `render.yaml` и покажет 4 ресурса.
4. Внизу — переменные, которые нужно ввести руками (`sync: false`):

   | Сервис | Переменная | Что ввести |
   |---|---|---|
   | `mise-api` | `Push__PrivateKey` | закрытый ключ из шага 0 (или оставить пустым) |
   | `mise-web` | `API_UPSTREAM` | `https://mise-api.onrender.com` |

   Остальные секреты (`Auth__SigningKey`, пароли демо-учёток и симулятора) Render сгенерирует сам.
5. **Apply**. Render начнёт создавать базу, Redis и собирать два Docker-образа.
   Сборка API на бесплатном плане — 5–10 минут; следить: Dashboard → сервис → **Logs**.

## 3. Проверка адреса API

1. Откройте сервис **mise-api** → сверху его адрес. Если это ровно `https://mise-api.onrender.com` — всё уже правильно.
2. Если Render дал другое имя (например, `https://mise-api-ab12.onrender.com`, когда `mise-api` занято):
   **mise-web → Environment → `API_UPSTREAM`** → вставьте этот адрес → **Save Changes** (web пересоберётся сам).
3. Проверка: `https://<адрес-api>/health` → `{"status":"Healthy", ...}`.

## 4. Открыть приложение

`https://mise-web.onrender.com` (адрес — в сервисе **mise-web**).

- **Демо-доступ**: кнопки «Склад · Повар · Менеджер» на экране входа (демо-ресторан «Mise · демо»).
- **Свой ресторан**: вкладка «Новый ресторан»; сотрудники — по приглашению (Пользователи → Приглашения).

После первого старта демо-ресторан уже со справочником (продукты, блюда, цены, замены), но без истории.

## 5. Демо-история за две недели (рекомендуется для презентации)

На бесплатном плане генератор истории внутри Render шёл бы слишком долго, поэтому история строится у вас
локально и переносится одним дампом (нужен только Docker).

1. Render → **mise-db** → **Connect** → вкладка **External** → скопируйте **External Database URL**.
2. В корне репозитория:
   ```powershell
   ./deploy/render/push-demo-data.ps1 -DatabaseUrl "<External Database URL>"
   ```
   Скрипт пересоздаст **локальную** базу демо-стека, построит историю (~2 мин), сделает дамп и зальёт его в Render
   (таблицы в базе Render заменяются).
3. Render → **mise-api** → **Manual Deploy** → **Restart service**.
4. Обновите сайт: на Главной горящие продукты, стоп-лист, заказы; в Отчётах — неделя к неделе.

> История заканчивается в момент запуска скрипта — делайте это незадолго до показа (за час-два — нормально).

## 6. Телефон: PWA и пуши

1. Откройте адрес **mise-web** на телефоне (Chrome на Android, Safari на iPhone).
2. Установка: Android — меню ⋮ → «Установить приложение»; iPhone — «Поделиться» → «На экран Домой»
   (на iPhone пуши работают только у установленного приложения, iOS 16.4+).
3. Войдите → **Ещё** → «Уведомления на телефон» → включить → разрешить в браузере.
4. Проверка: менеджер списывает партию / блюдо уходит в стоп — уведомление приходит на телефон.

## Обновления

Каждый `git push origin main` → Render сам пересобирает `mise-api` и `mise-web` (вкладка **Events** у сервиса).
Миграции БД применяются при старте API.

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| web не стартует: `host not found in upstream` | `API_UPSTREAM` пустой или с опечаткой — шаг 3 |
| Страница открылась, но вход висит / 502 | API ещё собирается или просыпается — подождать минуту, смотреть Logs у `mise-api` |
| `/health` — Unhealthy, redis | Key Value ещё создаётся; если долго — Dashboard → `mise-redis` → статус |
| Пуши не включаются | нет `Push__PrivateKey` у API, либо на iPhone приложение не установлено на экран «Домой» |
| Через месяц всё пропало | бесплатная база Render живёт 30 дней — создать заново (Blueprint → Sync) и залить историю (шаг 5) |

## Симулятор (по желанию, платно)

Живые заказы в реальном времени — фоновый worker, на бесплатном плане его нет. В `render.yaml` внизу —
закомментированный блок `mise-simulator`: раскомментировать, закоммитить, в Render — Blueprint → **Sync**.
План `starter` (около $7/мес). Управление — экран «Симулятор» у менеджера демо-ресторана.
